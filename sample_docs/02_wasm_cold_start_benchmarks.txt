# Document 2: Empirical Performance & Latency Benchmarks
# Research Study: Serverless Cold Start Comparison: Linux Containers vs. Wasmtime
# Published by: Distributed Systems & Systems Benchmarking Lab (2025)

1. Cold Start Latency Evaluation:
The primary operational challenge with traditional containerized serverless (e.g., AWS Lambda, Google Cloud Run) is cold-start latency caused by container image unpacking, Linux namespace creation, cgroup allocation, and language runtime booting (JVM or Node.js).

Empirical Measurements across 100,000 invocations:
- Standard OCI Container (Docker/containerd): Average cold start = 280 ms to 650 ms (p99: 1,420 ms).
- MicroVM (AWS Firecracker): Average cold start = 25 ms to 85 ms (p99: 140 ms).
- WebAssembly (Wasmtime Runtime): Average instantiation = 15 microseconds to 45 microseconds (p99: 80 microseconds).
Conclusion: Wasm achieves up to 1,000x faster cold-start initialization than traditional Linux containers.

2. Memory Overhead & Density:
- Container base image (Alpine Linux + Go binary): ~18 MB to 45 MB RSS per replica.
- Container base image (Java Spring Boot): ~350 MB to 700 MB RSS per replica.
- Compiled Wasm Component (Rust / WASI): ~1.8 MB to 4.2 MB total binary size, consuming < 5 MB active RAM.
- Density Multiplier: A single 64 GB worker node can host up to 10,000 concurrent active Wasm microservice instances, compared to only 150 to 300 Docker containers.

3. Throughput & Network IOPS:
- Throughput achieved on 100 Gbps network cards: 184,000 requests per second (RPS) per core using non-blocking epoll sockets.
- CPU Utilization: 85% lower CPU overhead compared to Kubernetes Envoy sidecar proxies.
